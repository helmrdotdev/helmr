The first release candidate for Helmr 0.2.0 brings the CLI, TypeScript SDK and
self-hosted runtime together around Agents, Sessions and Turns.

This is an early release for evaluation on a fresh installation.

## What you can try

- Define an agent and its computer in TypeScript, then deploy it to your own AWS infrastructure.
- Start from a Claude Code, Codex, OpenCode or Pi template.
- Continue conversations through Sessions and Turns, with human input from the Console, CLI or Slack.
- Configure scoped access for members and API keys, and inspect activity in the Console.

## Try the release candidate

Install this version explicitly; the default installer does not select release candidates:

```sh
curl -fsSL https://helmr.dev/install | bash -s -- --version v0.2.0-rc.1
```

Follow the [self-hosting guide](https://helmr.dev/docs/self-hosting/overview) to
set up a control plane and worker, then the [quickstart](https://helmr.dev/docs/quickstart).
Use this version of the CLI throughout; `helmr init` pins the matching SDK.
For an existing TypeScript project, install `@helmr/sdk@0.2.0-rc.1` explicitly.

CLI downloads are available below for macOS and Linux, on ARM64 and x86-64.
Self-hosting artifacts and image descriptors belong to the same signed
`release-index.json`. AWS AMIs are prepared separately by the operator.

## Compatibility

This release replaces the earlier 0.1.x SDK's Task, Sandbox and Run APIs with
the Agent, Template, Session and Turn APIs. Existing code needs updating.
There is no supported in-place database upgrade from earlier releases or previews
to this RC; use a new environment and retain existing data separately.

Please [report issues](https://github.com/helmrdotdev/helmr/issues) with your
Helmr version, operating system and steps to reproduce.
